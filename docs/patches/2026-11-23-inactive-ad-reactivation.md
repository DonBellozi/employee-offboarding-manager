## Поведение

Если у работника больше нет активной занятости ни в одной организации,
задача восстановления AD автоматически закрывается с причиной `inactive_again`.
Она исчезает из «Требуют внимания оператора». Учетка AD не включается,
не создаётся и вообще не запрашивается при таком закрытии.

Закрываются также старые предупреждения без подходящей завершённой цели AD:
раньше уборка выполнялась только для результатов JOIN с целями блокировки,
поэтому некоторые строки оставались открытыми навсегда.

Уборка выполняется при открытии главной страницы по локальным кадровым данным
и при фоновом рассмотрении возвращений. Отсутствие следующего вечернего
окна не мешает убрать старую строку при обновлении страницы.
Во время незавершённого импорта 1С задачи по промежуточным данным не закрываются.

Старые открытые формы «Обновить»/«Восстановить», в том числе для уже закрытой
задачи, возвращают оператора на главную без предупреждения и без ложного
сообщения об успешном восстановлении. Старый точный текст ошибки в URL
также больше не выводится. Остальные ошибки не подавляются.

Перед восстановлением AD кадровое состояние повторно читается после поиска
учёток. Если за время поиска подтверждённое возвращение исчезло, внешнего
включения не будет, задача закроется штатно.

Если работник остаётся активным хотя бы в одной организации, предупреждение
сохраняется. Реальные ошибки подключения AD и неоднозначности продолжают
требовать решения. При новом подтверждённом возвращении ранее отменённая
по неактивности задача может открыться вновь; успешно принятые решения
не сбрасываются. Порог автоматического восстановления 14 дней сохранён.

## Установка

1. Распаковать архив в `D:\Python\employee-account-manager` с заменой файлов.
2. Выполнить Commit и Push в PyCharm.
3. Выполнить Pull and redeploy в Portainer и убедиться, что запущен обновлённый образ.
4. Обновить главную страницу. При отсутствии выполняющегося импорта устаревшие
   предупреждения закроются автоматически; ручная чистка БД не нужна.
