## Раздел «Блокировка»

Поиск по ФИО, логину и email теперь включает:

- текущие кадровые записи всех организаций;
- сохранившиеся записи прежних работников, отсутствующих в текущей выгрузке;
- учётки, успешно созданные через систему, включая отдельное создание AD
  и частичный успех создания AD/почты; кадровая выгрузка для этого не нужна;
- пользовательские учётки AD из настроенной области поиска и ящики Zimbra
  из настроенных почтовых доменов, полученные фоновым обходом.

В результатах показан источник. Созданные через систему учётки попадают
в поиск сразу по истории создания. Ошибки создания, при которых ни одна
учётка не создана, не порождают цель для блокировки. Пароли в справочник
не копируются.

Отдельный поток обновляет AD/Zimbra при первом старте и далее раз в 6 часов
после успешного обхода. Время следующего обхода хранится в БД, поэтому
перезапуск не запускает новый полный обход раньше срока. При ошибке
сохраняется последний успешный снимок, повтор назначается через 15 минут.
На странице отображается время успешного обновления и ошибка, если она есть.
AD читается постранично. Ограниченный/частичный LDAP-ответ не заменяет снимок.
Zimbra читается через существующее подключение SSH и `gaa -v`, без изменения
ящиков. Поиск в браузере читает локальный справочник, не запускает обход.

Источники AD и Zimbra без подтверждённой общей связи представлены отдельно:
одинаковые ФИО или локальная часть адреса не связывают разные учётки.
Такая карточка выбирает учётку своего источника; для кадровой записи или
записи создания используются уже известные связи AD/почты.

Открытие карточки и выполнение блокировки повторно читают внешние системы.
Сохраняются прежние подтверждение, CSRF, журнал и очередь повторов. Если
одной из систем в выбранной карточке нет, пустая цель завершается как
«Отсутствует». Если задан конкретный логин/ID, но учётка не найдена, это
по-прежнему требует проверки и не подменяется пустой целью.

Сохранённые objectGUID/zimbraId являются определяющими: если объект исчез,
карточка и очередь не переключаются на новую одноимённую учётку или ящик
с повторно использованным адресом. Предыдущие учётки можно вручную блокировать
из раздела «Блокировка»; доступ исторических карточек для кадровой диагностики
по-прежнему явно ограничен чтением.

## Зависшее увольнение: invalid attribute type defaultNamingContext

Ошибка возникала при клиентской проверке служебного атрибута RootDSE по
обычной LDAP-схеме. Исправлены обе точки этой проверки:

- только на запросе RootDSE временно отключается проверка имён атрибутов;
- ответ RootDSE читается из сырого LDAP-ответа без создания schema-checked
  Entry/ObjectDef; затем исходный режим проверки восстанавливается.

Проверка кода результата LDAP, корня и домена, полного отсутствия объекта
по всему домену, перенаправлений и ошибок прав сохраняется.

Уже зависшие AD-цели с точной ошибкой
`invalid attribute type defaultNamingContext` автоматически переходят на
проверку без изменения AD. Для известного GUID сохраняется проверка GUID
и прежнего логина. При подтверждённом отсутствии завершается этап AD и
увольнение переходит в журнал штатным механизмом. Если объект найден,
нужно подтвердить сопоставление; исправление не блокирует найденный объект.
Если AD недоступна, выполняется повторная попытка.

Повторная обработка зависит от прежних кадровых условий: свежие источники,
отсутствие импорта, отсутствие активной занятости в других организациях,
наступивший срок с учётом отсрочки. Раздельные организационные контуры почты,
DSM и Техэксперта не изменялись. Расширение ручного поиска не означает
автоматической блокировки всех найденных учёток. IT Invent остаётся read-only;
1С Бухгалтерия и 1С ДО не добавлялись.

## Данные, проверки и установка

Добавлены только две таблицы: `blocking_directory_accounts` и
`blocking_directory_sync`. Они создаются при штатном старте приложения;
существующие кадровые записи не изменяются и не дополняются искусственными
работниками из AD. Идентификаторы строк справочника сохраняются при обновлении
и исчезновении объекта, чтобы ссылки на ручные операции оставались стабильны.

180 профильных pytest, py_compile изменённых Python-файлов, разбор Jinja,
синтаксис встроенного JavaScript и браузерная проверка на тестовых данных
при ширине 1440 и 390 пикселей прошли. Проверены поиск до кадровой выгрузки,
история работников, шестичасовой интервал, сохранение снимка при ошибке,
стабильные ID, CSRF, очередь, отсутствие подмены повторно использованных
логинов, старый сбой RootDSE и сохранение кадровых ограничений.

ZIP содержит 15 новых/изменённых файлов с путями от корня репозитория.
Удалений нет. Для установки заменить файлы и пересобрать/пересоздать
существующий контейнер приложения, сохранив настройки и тома.
Дополнительные библиотеки и ручные изменения БД не требуются.
Целостность ZIP, совпадение содержимого с исходниками и SHA-256 проверяются
при сборке архива.
