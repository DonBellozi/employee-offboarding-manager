# Удалённая конфликтующая AD-учётка больше не удерживает задачу

Основа: GitHub HEAD `2ab447e2c4aac3f16d85e9865c0436ace790ec0e`, скачанный
отдельно. Исходные версии четырёх изменяемых файлов совпали с HEAD после
нормализации CRLF/LF. Локальные изменения сохранены, GitHub не изменялся.

## Правило

Подтверждённое отсутствие известной AD-учётки является корректным завершением
её цели: блокировать уже нечего. Простое отсутствие логина в кадровой выгрузке,
пустой результат поиска в одной OU или ошибка LDAP не являются доказательством.

Новый `ActiveDirectoryService.confirm_user_absent`:

- требует включённой проверки AD и корректного сохранённого UUID objectGUID;
- получает defaultNamingContext из RootDSE и проверяет соответствие домену
  настроенной области поиска; отсутствие нельзя доказать на другом домене;
- ищет во всём домене GUID ИЛИ прежний sAMAccountName;
- подтверждает отсутствие только при LDAP result=0 и пустом ответе;
- ошибки, referrals, ограниченный/частичный результат, недоступность, отказ
  доступа, неполученный корень домена не считаются удалением;
- если объект переехал в другую OU, переименован с сохранением GUID или
  старый логин занят новой учёткой, отсутствие не подтверждается.

Это только LDAP-чтение. Приложение ничего не удаляет из AD.

## Применение к задачам

- В «Проверить завершение» допускается подтверждённое отсутствие выбранной
  учётки вместо её отключённого состояния.
- Дополнительно проверяются другие незавершённые реальные AD-цели того же run
  с сохранённым GUID. Если их отсутствие доказано, только эти цели получают
  already_completed / confirmed_absent. Текст кадровых записей, сопоставления
  и история целей сохраняются.
- Цели без известного GUID не объявляются удалёнными по одному логину.
  Неустранённая коллизия нескольких кадровых логинов/сопоставлений не разрешается
  случайным выбором оставшейся учётки: сначала требуется подтверждённое сопоставление.
- Если остающаяся выбранная AD активна, задача не завершается и команды её
  блокировки не вызываются. Другие существующие/непроверенные конфликтующие
  цели не скрываются. Результат пересчитывается штатно, без ложного success.
- Все кадровые защиты предыдущей проверки сохранены: роль admin, CSRF,
  подтверждение идентичности, отсутствие активной занятости во всех организациях,
  остановка при импорте, срок/отсрочка, повторная проверка после LDAP.
- В штатной фоновой обработке известная цель по GUID, исчезнувшая из AD,
  также корректно завершается после строгой проверки отсутствия. При этом
  исключён опасный fallback по старому логину: новая одноимённая учётка
  не будет автоматически заблокирована вместо удалённого объекта.
- Старые цели intervention сами по себе не переводятся в массовый автоповтор:
  для них используется явная кнопка «Проверить завершение».
- В журнале удалённая цель отображается «Отсутствует в AD (проверено)», а не
  «Уже была заблокирована». Если осталась подтверждённая заблокированная AD,
  показывается её логин, не логин удалённого конфликтующего объекта.
- Zimbra, DSM и Техэксперт не изменялись; их организационные правила независимы.

## Оператору

После установки и пересборки контейнера открыть сохранённое сопоставление
нужного увольнения и нажать «Проверить завершение». Для прежнего случая:
`/dismissals/101/ad-mapping` на вашем сервере. Если старый объект действительно
отсутствует и остальные цели обработаны, запись уйдёт в журнал сразу. При
отказе страница покажет причину; ошибки доступа не превращаются в успех.

Требуется предыдущая страница проверки завершения, включённая в указанный HEAD.
Данных реальной AD и производственной БД из среды разработки не изменяли.
