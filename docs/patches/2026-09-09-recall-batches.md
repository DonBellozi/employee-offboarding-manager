# Отзыв писем: Message-ID, пакет и прерывание

## Как пользоваться

- «По Message-ID»: укажите ID **из полученного письма** и автора. Получатель, дата и время не нужны. Автор нужен только для определения основного ящика и сохранения его «Отправленных», включая случай адреса-алиаса.
- Если ID в исходнике автора и доставленной копии различаются, они не считаются взаимозаменяемыми. Система не пытается угадать другой ID и не расширяет удаление до похожих писем.
- «По параметрам»: укажите получателя/группу, дату, время. При необходимости укажите ящик одного конкретного получателя. Тогда ID берётся из доставленной копии в этом ящике. Без этого поля исходник ищется в «Отправленных» автора.
- «Найти и удалить» отправляет одно задание на выполнение без дополнительного подтверждения. Если другой пакет выполняется, задание ждёт его завершения.
- «Добавить в пакет» только сохраняет задание. После добавления нескольких писем выберите запросы и нажмите «Запустить пакет» (до 50 запросов). Новые задания не подмешиваются в уже идущий проход.
- Пакет получает список ящиков один раз. Для каждого ящика используется общий поисковый запрос по выбранным Message-ID; статистика доступна по пакету и каждому заданию. Проверки результата удаления выполняются только в затронутых ящиках.
- «Прервать» останавливает пакет; «Отменить» убирает ожидающий пакет из выполнения. Новые команды удаления после обнаружения остановки не отправляются. Уже отправленная команда может завершаться до 180 секунд, после неё допускается проверка результата. Удалённые письма не восстанавливаются. Другие поставленные на выполнение пакеты сохраняют свою очередь.
- Неоднозначные результаты поиска по параметрам требуют выбора конкретного письма. Остальные задания пакета могут продолжить работу. Нечитаемые заголовки не превращают оставшийся результат в «единственное совпадение».

## Исправление чтения заголовков

Вместо вывода `getMessage`/`getMessage -v` используется `getRestURL /?id=<локальный номер>`: штатный REST Get Item возвращает MIME RFC822. Парсер читает только блок заголовков, поддерживает переносы и не принимает строки из тела за Message-ID. Письмо обрабатывается в памяти и не записывается в БД или файлы.

Официальная спецификация: https://wiki.zimbra.com/wiki/Zimbra_REST_API_Reference:Get_Item

## Обновление

1. Дождитесь завершения активных отзывов либо прервите их и дождитесь окончательного статуса.
2. Сделайте резервную копию БД и заменяемых файлов, затем распакуйте ZIP в корень проекта с сохранением путей.
3. Перезапустите приложение/контейнер. Новая таблица пакетов и два совместимых поля существующей таблицы добавляются штатным стартовым механизмом, без сброса данных.
4. Перезагрузите страницу. Адреса JS/CSS версионированы для обновления браузерного кэша.

После перезапуска незавершённые и ожидавшие выполнения пакеты помечаются прерванными с ошибкой; удаление самопроизвольно не возобновляется. Подготовленные, но ещё не запущенные задания остаются в пакете. История отменённых запросов сохраняется.

В старой схеме дата письма обязательна в БД. Для прямого ID это поле заполняется технической датой создания, но не участвует в поиске, не выдаётся за дату письма в интерфейсе и не попадает в журнал параметров как дата фильтра. Это позволяет обновить существующую БД без её пересоздания.

Проверки используют изолированные БД и имитацию Zimbra. Производственные ящики при разработке не изменялись. Доступ к странице, очереди, выбору письма и остановке остаётся только у роли «Администратор»; POST-запросы защищены CSRF.

Удалений файлов нет. Изменения в GitHub не отправляются.
